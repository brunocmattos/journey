# Landing do Journey — plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans pra executar este plano tarefa por tarefa. Os passos usam caixas de seleção (`- [ ]`) pra acompanhar o progresso.

**Objetivo:** a página pública em `/` pra quem não está logado, na direção A ("o próprio editor"): abertura com um fluxo animado no estilo do editor, quatro exemplos rodando no visualizador de verdade, as dores que o play mostra, como funciona, pra quem e o fechamento; "Entrar" e "Criar conta" na barra. Quem está logado continua indo pra empresa.

**Arquitetura:** a landing mora em `apps/web/src/landing/` e é renderizada pela raiz (`app/page.tsx`) quando não há sessão; o `proxy.ts` deixa só a raiz exata passar sem sessão. A abertura é um SVG próprio com os tokens do app (sem editor, sem `@journey/fluxo`, sem Supabase). Os exemplos são retratos (o mesmo tipo do link público) montados no código a partir dos modelos, mostrados pelo `Visualizador` num modo `embutido` que só carrega quando a seção chega perto da tela. O login com o Google sai do formulário da `/entrar` pra `lib/google.ts`, usado pela `/entrar` e pela landing, e o cliente do Supabase só baixa perto do clique.

**Tecnologia:** a mesma da etapa C (Node 22, TypeScript 5.9, Next.js 16.4, React 19.3, supabase-js 2.119, Vitest 3.2, Playwright 1.63). Sem dependência nova; sem migração.

**Spec:** `docs/superpowers/specs/2026-11-14-landing-design.md`.

## Decisões desta etapa

Cada uma foi comparada com a alternativa antes de entrar aqui.

| Decisão | Por quê | Alternativa recusada |
|---|---|---|
| **A landing na raiz, sem rota nova; só a raiz exata fica pública no `proxy.ts`** | `/` é o endereço que a pessoa digita; com sessão a raiz faz o que fazia (aceita convites e vai pra empresa). `//`, `/%2F` e `//e/x` continuam pedindo sessão | Uma rota `/inicio`, ou `startsWith('/')` (abriria tudo) |
| **Abertura em SVG próprio, com os tokens** (larga e, abaixo de 560 px, de pé) | Abre na hora e segue o tema; o editor de verdade pesa demais pro primeiro quadro; o desenho largo no celular teria letra de 7 px | O `Quadro` na abertura |
| **Exemplos: o `Visualizador` num modo `embutido`**, carregado a 240 px da tela, dentro de um error boundary | É o produto de verdade (play, decisões, diagnóstico) sem pesar a abertura; se o pedaço não baixar (rede, publicação nova no meio da visita), só ele some | Um visualizador novo; carregar junto com a página |
| **Os ciclos dos exemplos passam pela decisão do horário** | O motor só marca ciclo que anda sozinho, sem ninguém escolher e sem o tempo passar; as voltas com escolha aparecem no play, mas não são achado. Os exemplos mudaram, não o motor | Mudar o motor pra marcar qualquer volta (falso alarme em todo menu com "opção inválida") |
| **O play dos exemplos começa às 10h de um dia de atendimento** (`quandoDoExemplo`, pelo mesmo relógio do motor) | Quem abre de noite ou no domingo veria só "fora do horário"; e o e2e não depende da hora em que roda | A hora de agora |
| **No embutido:** a roda rola a página (zoom com Ctrl/Cmd), toque vertical rola, teclas do play só com foco dentro, gaveta ao lado a partir de 900 px e fechada abaixo, "Dar play" numa barra em cima do quadro | A página não pode ficar presa no quadro; no celular o fluxo aparece primeiro; o cartão do play só existe com o play andando | O comportamento do link público (página inteira) |
| **"Continuar com o Google" no botão do Google; "Entrar" e "Criar conta" na barra** | É o texto aprovado pelas diretrizes de marca do Google ("Criar conta com o Google" não é); com o Google desligado (local e testes), a chamada vira "Criar conta" e leva pra `/entrar?modo=criar` | O texto da primeira versão da spec |
| **`entrarComGoogle()` num lugar só (`lib/google.ts`)**: import dinâmico do cliente do Supabase, erro tratado, botão ocupado no primeiro clique, pré-carga no ponteiro ou no foco | O cliente do Supabase (uns 260 kB) saía no primeiro quadro da raiz por causa do botão; dois cliques gravavam dois verificadores PKCE e o primeiro voltava com erro | Import estático no botão |
| **`sessaoAtual` com o `cache` do React** | A raiz com sessão ia duas vezes ao Auth (a página e o `usuarioAtual`) | Duas chamadas de `getUser` |
| **A conferência dos chunks fora do `npm test`, em `npm run test:build`** (faz o build antes; sem build, falha) | Lendo um build velho, o teste dava verde falso | Ler o último `.next` que existir |

**Gotchas que o ensaio achou:**
- **`ciclo_sem_tempo` só sai em ciclo sem escolha:** uma volta que passa por um menu (decisão com opções) não vira achado. Os exemplos foram montados pra isso, e o teste de unidade confere os achados exatos de cada um.
- **O e2e roda com o Google desligado:** a chamada da landing nos testes é "Criar conta". O caminho com o Google é coberto pelos testes de unidade (`lib/google`, o botão e a página renderizada com as variáveis).
- **Tipos velhos no `.next`:** se o `next typegen` reclamar de rota que não existe mais, apague `apps/web/.next` e rode de novo.
- **Erro do servidor "The destination stream errored while writing data"** pode aparecer no log da ponta a ponta numa navegação interrompida no meio do envio; não faz teste falhar.
- **Error boundary e testes sem DOM:** o React no servidor não usa error boundary; o teste do `SemQuebrar` chama os métodos dele direto.
- **O `cache` do React não guarda nada fora do servidor:** a ida única ao Auth não tem teste de unidade.

`apps/web/src/lib/google.ts`:

```ts
/**
 * Entrar com o Google pelo navegador (a /entrar e a landing). O cliente do Supabase vem por import dinâmico: a landing
 * abre sem ele, e `preCarregarGoogle` (no ponteiro ou no foco do botão) adianta o download. O código do PKCE fica num
 * cookie deste navegador, e a volta é pelo /auth/callback.
 */
const cliente = () => import('@/lib/supabase/navegador');

/** Começa a baixar o cliente do Supabase antes do clique. Falhar aqui não importa: o clique tenta de novo. */
export const preCarregarGoogle = (): void => void cliente().catch(() => {});

/**
 * Pede o login do Google. Devolve true quando o pedido saiu (o navegador já está indo pro Google) e false quando nem
 * saiu (o cliente não baixou, o provedor está desligado, sem rede): quem chama diz pra pessoa.
 */
export async function entrarComGoogle(): Promise<boolean> {
  try {
    const { supabaseNavegador } = await cliente();
    const { error } = await supabaseNavegador().auth.signInWithOAuth({
      provider: 'google',
      options: { redirectTo: `${window.location.origin}/auth/callback` },
    });
    if (!error) return true;
    console.error('[Google]', error.message);
  } catch (e) {
    console.error('[Google]', e);
  }
  return false;
}
```

```ts
/**
 * As abas dos exemplos: o nome, a dor em uma frase e a cor do canal de cada um (a dos canais padrão). Sem o
 * @journey/fluxo: as abas e as miniaturas vêm no primeiro carregamento; os retratos (exemplos.ts), só com o visualizador.
 */
export const ABAS = [
  { chave: 'ura', nome: 'URA telefônica', dor: 'O cliente que aperta 9 e não chega em lugar nenhum.', cor: '#1e8bdc' },
  { chave: 'whatsapp', nome: 'Suporte no WhatsApp', dor: 'O bot que manda o cliente de volta pro começo.', cor: '#159e5a' },
  { chave: 'email', nome: 'SAC por e-mail', dor: 'O chamado que fica dois dias parado antes de alguém escalar.', cor: '#c98410' },
  { chave: 'credito', nome: 'Esteira de crédito', dor: 'A proposta parada horas na análise manual.', cor: '#3a6a88' },
] as const;

export type ChaveAba = (typeof ABAS)[number]['chave'];

/**
 * O id do botão da aba (`aba-ura`). Diferente do hash: com um elemento de id `exemplo-ura`, o navegador rolaria até a
 * aba, e não até o começo da seção.
 */
export const idDaAba = (chave: ChaveAba): string => `aba-${chave}`;

/** O endereço de um exemplo: `#exemplo-ura`, pra dar pra mandar o link dele. */
export const hashDaAba = (chave: ChaveAba): string => `#exemplo-${chave}`;

/** A aba de um endereço (`#exemplo-credito`), ou null quando o hash não é de exemplo nenhum. */
export function abaDoHash(hash: string): ChaveAba | null {
  const chave = /^#exemplo-([a-z]+)$/.exec(hash)?.[1];
  return ABAS.find((a) => a.chave === chave)?.chave ?? null;
}

/** A aba seguinte numa tecla da lista de abas (setas, Home e End), dando a volta nas pontas; null pras outras teclas. */
export function abaDaTecla(atual: ChaveAba, tecla: string): ChaveAba | null {
  const i = ABAS.findIndex((a) => a.chave === atual);
  const n = ABAS.length;
  const j = tecla === 'Home' ? 0 : tecla === 'End' ? n - 1 : tecla === 'ArrowRight' ? (i + 1) % n : tecla === 'ArrowLeft' ? (i - 1 + n) % n : null;
  return j === null ? null : ABAS[j]!.chave;
}
```

```tsx
 * escolhido. Antes de carregar, a área já tem a altura final e mostra a miniatura do exemplo, pra a página não pular. A

export function Exemplos() {
  const [aba, setAba] = useState<ChaveAba>('ura');
  const [perto, setPerto] = useState(false);
  // O visualizador montou: daí em diante o painel tem botões e sai do Tab ele mesmo.
  const [vivo, setVivo] = useState(false);

  const lista = useRef<HTMLDivElement>(null);

  // id do hash, então quem rola até a seção é daqui.
  useEffect(() => {
    const ler = () => {
      const k = abaDoHash(location.hash);
      if (!k) return;
      setAba(k);
      document.getElementById('exemplos')?.scrollIntoView();
    };
    ler();
    addEventListener('hashchange', ler);
    return () => removeEventListener('hashchange', ler);

  useEffect(() => {

    if (!el) return;

        if (!es.some((e) => e.isIntersecting)) return;
        setPerto(true);
        io.disconnect();
```

```tsx
'use client';

import Link from 'next/link';
import { useEffect, useState } from 'react';
import { BotaoGoogle } from '@/componentes/BotaoGoogle';
import type { DestinoDaLanding } from '@/lib/acesso';
import { entrarComGoogle, preCarregarGoogle } from '@/lib/google';

/**
 * Um botão de entrar da landing. Pra uma página, é um link. Pro Google, abre o login dele daqui (`entrarComGoogle`, com
 * o cliente do Supabase baixado só quando o ponteiro ou o foco chega no botão); se o pedido nem sai (provedor
 * desligado, rede), vai pra /entrar com o aviso do Google, como quem cancelou lá. Depois do primeiro clique, o botão
 * fica ocupado e o segundo não pede de novo.
 * - `google`: o botão do Google, no padrão da marca (a chamada da abertura e do fechamento);
 * - `pilula`: o botão escuro da barra ("Criar conta"); `texto`: só o texto ("Entrar").
 */
export function BotaoDeEntrar({ destino, rotulo, jeito }: { destino: DestinoDaLanding; rotulo: string; jeito: 'google' | 'pilula' | 'texto' }) {
  // Antes de o React assumir a página, o clique não faria nada: o botão fica desligado até lá.
  const [pronto, setPronto] = useState(false);
  useEffect(() => setPronto(true), []);
  const [ocupado, setOcupado] = useState(false);
  // Quem volta do Google pelo "voltar" do navegador acha a página como deixou (cache de página): o botão solta.
  useEffect(() => {
    const voltou = (e: PageTransitionEvent) => e.persisted && setOcupado(false);
    addEventListener('pageshow', voltou);
    return () => removeEventListener('pageshow', voltou);
  }, []);
  const classe = jeito === 'pilula' ? 'l-pilula' : 'l-texto';

  if (destino.tipo === 'pagina')
    // Sem o Google ligado, a chamada vira o botão escuro, grande.
    return (
      <Link className={jeito === 'google' ? 'l-pilula grande' : classe} href={destino.href}>
        {rotulo}
      </Link>
    );

  async function comGoogle() {
    if (ocupado) return;
    setOcupado(true);
    if (!(await entrarComGoogle())) window.location.assign('/entrar?erro=google');
  }

  if (jeito === 'google') return <BotaoGoogle disabled={!pronto} onClick={comGoogle} rotulo={rotulo} ocupado={ocupado} aoChegar={preCarregarGoogle} />;
  return (
    <button
      className={classe}
      type="button"
      disabled={!pronto}
      aria-disabled={ocupado || undefined}
      onClick={comGoogle}
      onPointerEnter={preCarregarGoogle}
      onFocus={preCarregarGoogle}
    >
      {rotulo}
    </button>
  );
}
```

```ts
  entryJSFiles?: Record<string, string[]>;
```
